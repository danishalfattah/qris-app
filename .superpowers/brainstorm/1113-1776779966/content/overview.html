Penyesuaian QRIS UI dengan API Spec

Overview perubahan yang diperlukan — kita akan bahas satu per satu

Kondisi Saat Ini

Semua data di-mock secara lokal di lib/mock-data.ts. Belum ada API call nyata.

Area Perubahan Berdasarkan API Spec

1

Auth — Login & Register

Login sekarang pakai username (bukan email). Ada endpoint register baru dengan initial_balance. Response berisi JWT token + account_id + balance.

Perubahan UI: Form login ganti field email → username. Tambah halaman /register.

2

QRIS Inquiry — Setelah Scan

GET /api/qris/inquiry/{qris_payload} mengembalikan merchant_id, merchant_name, terminal_id, city, fixed_amount, inquiry_id.

Perubahan UI: Tampilkan city & terminal_id. Jika fixed_amount = 0, tampilkan input nominal.

3

Payment — Konfirmasi Bayar

POST /api/qris/payment butuh inquiry_id, amount, payment_method: "balance", pincode (6 digit). Response 202 dengan transaction_id.

Perubahan UI: Flow sudah mirip, perlu mapping field ke format API.

4

Transaction Status — Polling

GET /api/qris/status/{transaction_id} mengembalikan status PENDING/SUCCESS/FAILED + final_balance.

Perubahan UI: Layar "Processing" perlu polling endpoint ini sampai status berubah dari PENDING.

5

Balance — Dari Auth Response

API tidak punya endpoint /balance tersendiri. Balance tersedia dari: login response, status transaksi (final_balance).

Implikasi: Balance perlu disimpan di auth context dan di-update setelah transaksi.

6

Transaction History — Admin Endpoint

GET /api/admin/transactions hanya untuk admin. Field yang tersedia: transaction_id, account_id, merchant_id, amount, status.

Perubahan UI: History perlu disesuaikan dengan field yang ada. Filter periode mungkin client-side.
