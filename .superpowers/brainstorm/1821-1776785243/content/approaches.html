Pendekatan Implementasi

Pilih bagaimana kita menyusun layer API di project ini

A

API Service Layer Terpusat — Direkomendasikan

Buat satu file lib/api.ts berisi semua fungsi API (login, register, inquiry, payment, status). Semua halaman memanggil fungsi dari sini. JWT token dikelola di lib/auth.tsx.

Pros

  • Mudah di-maintain — satu tempat untuk semua API call
  • Token management terpusat
  • Konsisten dengan pola project yang sudah ada

Cons

  • Perlu refactor beberapa halaman
B

Fetch Langsung di Tiap Halaman

Setiap halaman langsung panggil fetch() ke API tanpa abstraksi. Token diambil dari context di tiap komponen.

Pros

  • Lebih cepat dikerjakan per halaman

Cons

  • Duplikasi logic token di banyak tempat
  • Sulit di-maintain jika base URL berubah
C

Next.js Route Handlers sebagai Proxy

Buat app/api/* di Next.js sebagai proxy ke backend. Frontend hanya memanggil route lokal.

Pros

  • Bisa menyembunyikan token dari browser

Cons

  • Overkill untuk capstone
  • Menambah complexity tanpa manfaat jelas
